## 1. 概要

就活生が、応募企業・選考状況・予定・タスクを一か所で管理し、面接のふりかえりで見つけた課題を次の面接に活かしていくWebアプリ。PCとスマホの両方で使い、スマホはPWAとしてホーム画面に追加して使う。

| 項目 | 内容 |
| --- | --- |
| 利用者 | 就活生（自分以外にも公開。100人未満を想定した会員制） |
| サーバー | ロリポップ！ハイスピードプラン（LiteSpeed、SSHあり、cron最短1分） |
| サーバー言語 | PHP 8.2以上（フレームワークなし。`public/index.php` を入口にした素のPHP） |
| データベース | 本番：ロリポップの MySQL 8.4 ／ 開発：XAMPP の MariaDB。utf8mb4 |
| フロント | HTML / CSS / JavaScript。CSSとJSはプロトタイプから移植 |
| 配信形態 | PWA（manifest.json + Service Worker）、HTTPS必須 |
| 通知 | Web Push（VAPID）。`minishlink/web-push` を使う |
| 定期処理 | cron：1分ごとに通知送信、5分ごとにカレンダー同期 |
| 外部連携 | Google Calendar API のみ（iPhoneはGoogleアカウントを追加してアップルカレンダーで表示） |
| 開発環境 | Windows + XAMPP + Composer + VS Code（手順は `README.md`） |

### ブランド

- アイコン：「晴れの日の出」。空色の背景 `#3a7bd5`、太陽 `#ffd66b`、4つに区切った地平線。状態によって変化させない
- PWAのテーマ色：`#3a7bd5`
- アプリのアクセント色：ライト `#2f6fc9` ／ ダーク `#7fb0f5`
- ライト／ダークは端末の設定に合わせる（色はすべてCSS変数で定義。値はプロトタイプの `:root` をそのまま使う）
- 画像一式は `public/icons/`（192・512・maskable・apple-touch-icon・favicon・svg）

## 2-2. PC版とスマホ版の違い

PC版とスマホ版は**同じURL・同じHTML**で、画面の幅でレイアウトだけを切り替える（レスポンシブ）。**画面幅860px以下をスマホ版**とする。CSSでは `@media (max-width:860px)` で切り替える（プロトタイプでは `html.mob` のついたルールがスマホ版の指定）。機能・データはPCとスマホで完全に共通。

### 共通部分のレイアウト

| 部分 | PC版 | スマホ版 |
| --- | --- | --- |
| メニュー | 左に縦のサイドメニュー（ホーム・成長記録・タスク・企業一覧・予定・管理・設定）。下に「追加する」ボタン群（ふりかえり・タスク・企業・予定）と課題の記録 | 左メニューは隠す。画面下に固定の下部ナビ（ホーム・成長・タスク・企業・予定）。アイコン26px、文字つき、iPhoneの下の余白（safe-area）を確保 |
| ヘッダー | 左メニューの上にロゴと通知ベル | 画面上に固定の上部バー（高さ76px）：左にロゴ（40px）、右に設定ボタンと通知ベル（各46px） |
| 追加ボタン | 左メニューの「追加する」 | 右下に「＋ 企業を追加」のような文字つきボタン（高さ52px、下部ナビの上に固定）。開いている画面に合わせて文字と中身が変わる（ホーム・企業→企業を追加、予定→予定を追加、タスク→タスクを追加、それ以外→ふりかえりを書く）。下へスクロール中は丸い「＋」に縮み、止まると文字が戻る。一覧が空のときは、画面の中にも「＋ 最初の企業を登録する」などの大きなボタンを出す（2026-10-13 追加） |
| 管理画面への入口 | 左メニューの「管理」 | なし（管理画面はPC版だけ。スマホで開くと「パソコンで開いてください」と表示） |
| いま意識すること（帯） | 画面上部に固定 | 上部バーのすぐ下に固定 |
| デモ画面の青い帯 | 帯の文章を全部表示 | 「デモ画面（変更は保存されません）」と短くして、ボタンを優先 |
| 詳細・編集画面 | 右から幅460pxの画面がスライドして出る（面接前カードは620px） | 画面いっぱいに表示 |
| お知らせ（トースト） | 画面下 | 下部ナビに重ならない位置（下から100px） |
| 本文の余白 | 広め | 左右16px、下は下部ナビと＋ボタンに隠れないよう160px |

### 画面ごとの違い

| 画面 | PC版 | スマホ版 |
| --- | --- | --- |
| ホーム | 「いま意識すること」と「課題の記録」、「予定」と「やること・締切」を2列で並べる | すべて1列に縦に並べる |
| 選考の進捗 | 5段階を横1列 | 段階の数字を折り返して表示 |
| 面接前カード（ホーム） | 日付・内容・「面接前カードを開く」を横に並べる | 日付と内容を横に、「面接前カードを開く」はカードの下に横幅いっぱい |
| 面接前カード（詳細） | 場所と持ち物を2列 | 1列 |
| 企業一覧のボード | 列を画面幅に並べる | 1列240pxで横スクロール（スクロールバーは上部） |
| わたしの軸 | 順位・企業・マッチ度・評価を1行 | 2段に組み替え（上：順位・企業・マッチ度、下：評価）。絞り込みの見出しは省略 |
| 予定のカレンダー | 日付のマスに予定名を最大3件表示 | 日付のマスには色の点だけ表示し、日付を押すと下にその日の予定一覧 |
| 管理画面のアクセス数 | 数字のタイルを横4つ | 2つずつ2段 |

### スマホ版だけの決まり

- ホーム画面に追加（PWA）して使うことを前提にする。アイコン化の案内（3-2）はスマホで開いたときに最も目立たせる
- iPhoneのノッチや下のバーに隠れないよう、`viewport-fit=cover` と `env(safe-area-inset-*)` で余白を取る
- 文字入力欄は16px以上にする（iPhoneで入力時に画面が拡大されないように）
- ボタンなど押せる場所は、指で押しやすい大きさ（目安44px以上）にする

## 3. 未ログイン時とはじめての登録

### 3-1. 未ログインの人にはデモ画面を見せる

- ログインしていない人が `/` を開くと、**本物と同じ画面をサンプルデータで表示する（デモ画面）**
- デモ画面ではすべての操作を試せるが、**何も保存しない**（サーバーにも書き込まない）
  - 実装：サンプルデータはJSONで固定して返し、デモ中の変更はブラウザのメモリ上だけで扱う。保存APIはログインしていないと 401 を返す
- 画面の上に青い帯を固定表示：「デモ画面です。サンプルのデータで自由に試せます（変更は保存されません）」＋「ログイン」「無料で登録」ボタン
- PCは左メニューのいちばん下にも「ログイン」「無料で登録」ボタン
- 設定画面のアカウント欄は、ログアウトの代わりに「ログイン」「無料で登録」
- デモでは管理画面のメニューは出さない
- ログイン画面・登録画面・説明ページは、デモ画面の帯からいつでも開ける。説明ページには「デモを見る」も置く

### 3-2. 新規登録したら、アイコン化のページを必ず見せる

アイコン化（ホーム画面に追加）を何より優先する。

1. 新規登録が終わったら、ホームではなく**アイコン化のやり方ページに移動する**（ホーム画面から開いている＝すでに追加済みの場合は除く）
2. ページの上に「登録ありがとうございます！まずはホーム画面に追加しましょう」と、通知はホーム画面に追加したときだけ届くことを表示する
3. パソコンで登録した人には「スマホで haruharu.tech を開いて同じ手順で追加してください」と表示する
4. ページの下に2つのボタン
   - 「ホーム画面に追加しました」→ `install_done = 1` にしてホームへ
   - 「あとで追加する」→ ホームへ（強制はしない）
5. 追加するまでは、**ホームのいちばん上に「ホーム画面に追加しよう」の案内**を出し続ける（「やり方を見る」「×」）
   - ×で閉じたら `install_dismissed = 1`。以後は設定の「ホーム画面に追加（アイコン化）のやり方」から見られる
   - ホーム画面から開いているとき（`display-mode: standalone` または `navigator.standalone`）は出さない
6. ふつうのログインでは、アイコン化のページには飛ばさない

### 3-3. ログインと保持期間

- ログインしたままの期間（2026-10-12 決定）
  - **スマホ版**（幅860px以下）：**90日間**（PWAでも同じ）。チェック欄は出さない
  - **PC版**：ログイン画面に「ログインしたままにする（7日間）」のチェック欄。**最初からチェックあり＝7日間**。外すとブラウザを閉じるまで（DB側も12時間で期限切れ）
  - 新規登録はチェック欄なしで、PC版は7日間・スマホ版は90日間
- ログイン時にランダムなトークンを発行し、HttpOnly・Secure・SameSite=Lax のCookieに上の期間で保存。DBの `auth_tokens` には selector と、トークンのハッシュ（SHA-256）だけを保存する
- 期限はログインした日から数える（使っても延びない）。切れたら再ログイン
- ログアウトした端末のトークンはすぐ削除。パスワード変更時は全端末のトークンを削除。設定に「すべての端末からログアウト」も用意する
- パスワードは `password_hash()` / `password_verify()`。8文字以上
- 状態が「停止中」の会員はログインできない
- iPhoneはSafariとホーム画面のPWAでログイン状態が別々。追加後にPWA側で一度ログインするよう案内する（アイコン化ページの手順5に記載済み）

## 4. 各画面の仕様

### 4-1. ホーム（上から順に）

1. ホーム画面に追加の案内（3-2の条件のときだけ）
2. **選考の進捗**：気になる→エントリー→書類選考→面接（一次・二次・最終の合計）→内定 の社数をメーターで表示。見送りは含めない。説明文は出さない
3. **面接前カード**：2日以内に面接があるときだけ。日付・企業・内容・場所・持ち物・意識すること、オンラインURLがあれば「Zoomに参加」「URLをコピー」、「面接前カードを開く」
4. 今日の日付と2週間以内の予定件数
5. **いま意識すること**（最大3件、メーターつき）と **課題の記録**（ふりかえり数・意識中・身についた）
6. 未ふりかえりの声かけ（終わった面接などでふりかえっていないもの）
7. これからの予定（2週間以内、最大6件）
8. 今日までのやること：未完了（今日・明日まで）を上、今日完了したものはチェック済みで下に
9. 締切が近いもの（ES締切・Webテスト、最大5件）

### 4-2. 課題のメーター（ふりかえり）

- ふりかえりの入力：どの予定のふりかえりか、企業、手応え（散々／いまいち／ふつう／まずまず／手応えあり）、聞かれたこと（任意）、次に活かしたいこと（1件40文字まで、複数可）
- 書いた「次に活かしたいこと」が課題になり、ホームの「いま意識すること」に出る
- 次のふりかえりで、意識中の課題ごとに評価を選ぶ
  - できなかった +0% ／ 少しできた +15% ／ だいたいできた +30% ／ できた +50%
- 合計が100%になった課題は「身についたこと」に移る（その日が身についた日）
- 評価は `lesson_evals` に記録として残し、メーターは毎回合計で計算する
- レベル・経験値などのゲーム要素は入れない

### 4-3. 面接前カード

面接の予定ごとに、準備に必要な情報を1画面にまとめる。

- 日時・場所・オンラインURL・持ち物
- この面接で意識すること（意識中の課題とメーター）
- この企業で前回聞かれたこと
- ほかの面接でよく聞かれたこと（ふりかえりの「聞かれたこと」を集計、回数つき）
- 志望動機・企業メモ
- この企業の未完了タスク
- わたしの軸でのマッチ度
- 開き方：ホームの面接前カード、予定の編集画面、前日の通知のタップ

### 4-4. オンライン面接のURL

- 予定に「オンライン面接のURL」欄。**https:// から始まるものだけ保存**（それ以外はエラー表示）
- URLから名前を判定してボタン名にする：Zoom／Microsoft Teams／Google Meet／Webex（それ以外は「オンライン面接に参加」）
- 「参加」ボタンは新しいタブで開く（`rel="noopener"`）。「URLをコピー」はクリップボードにコピーし、失敗したらその旨を表示

### 4-5. タスク

- クイック追加（やること・企業・期限）、よく使うタスク（企業研究／ESの下書き／証明写真を撮る／成績証明書を発行／OB・OG訪問の連絡／面接の練習／お礼メールを送る）
- 期限別グループ：期限切れ／今日／7日以内／それ以降／期限なし。完了タブ
- タスク名60文字まで
- 通知日時の設定（6章）

### 4-6. 企業一覧

- 表示は「ボード」「リスト」「わたしの軸」の3つ。**最後に選んだ表示を `user_settings.company_view` に保存**して次回もその表示で開く（PC・スマホ共通）
- ボード：選考段階ごとの列。ドラッグで段階を移動。横スクロールのバーは上部に置く
- 企業の項目：企業名、業界、選考段階、志望度（★1〜5）、企業のHP（ホームページ）、採用ページURL、マイページ情報（**ログインIDなどのメモ用。パスワードは書かないよう注意書きを出す**）、メモ、わたしの軸の評価
- 企業詳細の上部に「企業のHPを開く」「採用ページを開く」ボタン（URLを入れたときだけ。新しいタブで開く）。URL は http(s) だけ受け付け、「example.co.jp」のように書いたら https:// を補う
- 企業詳細から、その企業の予定・タスク・学んだことを見られる

### 4-7. わたしの軸と内定の比較

- 利用者が会社選びの軸と重み（0〜5、0は使わない）を決める。初期値：志望度×5、やりたいこと×5、給与×3、勤務地×3、働き方×2。軸の名前は12文字まで、追加・削除・並べ替えができる
- 企業ごとに各軸を★1〜5で評価。志望度は企業の★をそのまま使う
- **マッチ度 ＝ Σ(重み×★) ÷ Σ(重み×5)**（％、未評価の軸は計算から除く）。高い順に並べる
- 絞り込み：表示する範囲（選考中・面接中・内定など）と、「○○が★4以上」のような条件
- 最大3社にチェック → 軸ごとの評価とマッチ度を横に並べた比較表。各軸でいちばん高い会社に色。「内定の会社を比べる」で内定の会社をまとめて選択

### 4-8. 予定

- 「リスト」「カレンダー（月表示）」の切替。**最後に選んだ表示を `user_settings.schedule_view` に保存**
- 種類：説明会／ES締切／Webテスト／面接／インターン／その他
- 項目：種類、企業、内容、日付、時刻、場所、オンライン面接のURL、持ち物・メモ
- カレンダーで日付を押すと、その日の予定一覧と「この日に追加」
- 終わった予定（面接・説明会・インターン・Webテスト）から「ふりかえる」

### 4-9. 通知ベル

- PCは左メニュー上部、スマホは上部バーにベル。未読数をバッジ表示
- 中身：送信したタスク・予定のリマインド、未ふりかえりの声かけ、面接前カードの案内
- 押すと該当のタスク・予定・面接前カードを開いて既読に。「すべて既読にする」あり
- プッシュを許可していない端末でも、ベルで同じ内容を確認できる
- 90日を過ぎた通知は自動で削除

### 4-10. 設定（上から順に）

1. **プッシュ通知**：「この端末で通知をオンにする」、「ホーム画面に追加（アイコン化）のやり方」
2. **タスクの自動通知**（アコーディオン）
3. **予定の自動通知**（アコーディオン）
4. **Googleカレンダー連携**：「Googleと接続」とiPhoneでの見え方の手順
5. **アカウント**（いちばん下）：90日保持の説明、ログアウト（デモ中はログイン・登録）

### 4-11. アイコン化のやり方

- iPhone／Android をタブで切替（端末から初期タブを自動判定）
- iPhone：①Safariで haruharu.tech を開く ②共有ボタン ③「ホーム画面に追加」 ④右上の「追加」 ⑤アイコンから開いてログインし、通知をオン
- Android：①Chromeで開く ②右上の︙ ③「ホーム画面に追加」（機種により「アプリをインストール」） ④「インストール」 ⑤アイコンから開いて通知をオン
- 各手順に絵を付ける（絵はプロトタイプのSVGをそのまま使う）
- iPhoneの注意：通知は iOS 16.4 以降。Safariとアプリはログインが別
- 登録直後に開いたときの表示は 3-2

### 4-12. 管理画面（管理者だけ）

- `users.role = 'admin'` のアカウントだけが開ける。会員がURLを直接開いても 403
- PC版だけ：左メニューの「管理」から開く。スマホ版には入口を置かない（2026-10-12 決定）
- 会員一覧：名前、メールアドレス、登録日、最終ログイン、状態（利用中／停止中）。検索あり
- 会員の停止ボタンは置かない（2026-10-12 決定）。どうしても止めるときは phpMyAdmin で `users.status = 'stopped'` にする（ログイン不可になり、データは消えない）
- **会員の企業・予定・タスク・ふりかえりの中身とパスワードは管理者にも見せない**
- アクセス数：会員数、直近7日に使った人、今日と直近7日のページビュー（前の7日との比較）、直近14日のページビューの棒グラフ
- 数え方：1日・1訪問者ごとに1行（`access_daily`）。ページを開くたびに views を+1。**IPアドレスは保存しない**
- 最初の管理者は、自分で会員登録したあと phpMyAdmin で `UPDATE users SET role='admin' WHERE email='自分のメール';`
- 利用規約・プライバシーポリシーに「運営者は会員の名前・メールアドレス・利用状況を確認できる」ことを書く

## 6. 通知（タスク・予定）

### 6-1. 通知日時の決め方

| 対象 | 初期値 | 選べるタイミング |
| --- | --- | --- |
| タスク | 前日 20:00、当日 21:00 | 3日前・2日前・前日・当日 ＋ 時刻 |
| 予定 | 前日 20:00、開始の1時間前 | 上記 ＋ 開始の15分前〜3時間前 |

- 初期値は設定画面で最大5件まで自由に追加・変更・削除でき、「初期値に戻す」もある
- 期限のあるタスク・予定には、初期値の通知を自動で付ける
- タスク・予定ごとに、自動の通知を外したり、通知日時を手動で追加したりできる（1件につき手動は最大3件、5分単位）
- 期限なしのタスクも手動で通知日時を設定できる
- 設定の保存形式（`user_settings.task_reminders` / `event_reminders` のJSON）：`{"d":-1,"t":"20:00"}`＝前日20時、`{"d":0,"t":"21:00"}`＝当日21時、`{"m":60}`＝開始60分前

### 6-2. 通知の内容

- タスク：タイトル「タスクの期限が近づいています」、本文「にじいろ商事｜ESの下書きを仕上げる（今日まで）」
- 予定：タイトル「明日の予定」など、本文「はれまシステムズ｜二次面接 14:00」。面接は前日の通知から面接前カードを開く
- タップで該当画面を開く。Android・PCは「完了にする」ボタンも付ける（iPhoneはボタン非対応のためタップで開く）

### 6-3. 送信と取り消し

- cron（1分ごと）で `reminders` の未送信かつ予定時刻を過ぎたものを送信し、`sent_at` を入れて二重送信を防ぐ
- タスクを完了・削除したら未送信の通知を削除。期限を変えたら自動通知を付け直す
- 複数端末で許可していれば全端末に送る。送信先が 404 / 410 を返したらその端末の登録を削除
- 送った通知は `notifications`（ベル）にも入れる

### 6-4. 通知の許可

- 許可は設定の「この端末で通知をオンにする」を押したときだけ求める（ページを開いた瞬間には求めない）
- iPhone・iPadは iOS 16.4以降で、ホーム画面に追加したときだけ届く。未追加のiPhoneにはアイコン化の手順を案内
- Androidはブラウザのままでも届くが、ホーム画面への追加を推奨

## 7. Googleカレンダー連携

- 就活日和はGoogleカレンダーとだけ連携する。iPhoneは「設定 → カレンダー → アカウント → アカウントを追加 → Google」で、アップルカレンダーアプリにも同じ予定が出る
- 対象はGoogleに作る専用カレンダー「就活日和」だけ（私用の予定は読まない）
- 権限は最小の `https://www.googleapis.com/auth/calendar.app.created`
- **iCloud・Googleのパスワードは一切預からない**。Googleのトークンは libsodium で暗号化して `calendar_accounts.credentials` に保存
- 公開ステータスは「本番環境」（「テスト中」だとトークンが7日で切れるため）。OAuth審査は受けない（利用者は累計100人まで、接続時に「Googleはこのアプリを確認していません」の画面が出る → 「詳細 → 就活日和に移動」で進む、と接続画面で案内）

| 経路 | 方法 | 反映まで |
| --- | --- | --- |
| 就活日和 → Google | 保存時にAPIで送信 | 数秒 |
| Google → 就活日和 | 変更通知（events.watch）＋差分取得（syncToken）、5分ごとの確認も | 数秒〜5分 |
| Google ⇄ アップルカレンダー | iPhone・Macの標準機能 | 数秒〜数分 |

同期のルール

- 追加・変更・削除をすべて同期。範囲は過去30日〜1年先
- 両方で変更されたら、更新時刻が新しいほうを採用
- `events.google_event_id` と `google_etag` で、自分が書いた変更を再度取り込む「同期のループ」を防ぐ
- Google側で作られた予定は、タイトルに登録済みの企業名があればその企業に紐づけ、種類はタイトルの言葉から推定（なければ「その他」）
- 書き出すタイトルは「企業名｜内容」（例：はれまシステムズ｜二次面接）。説明欄に種類・場所・オンラインURL・就活日和へのリンク
- タスクは同期しない
- アップルカレンダーで追加するときは「就活日和」カレンダーを選ぶ必要がある（iCloudの「ホーム」などに入れた予定は届かない）。設定の案内で「デフォルトのカレンダー」を「就活日和」にしてもらう
- 「連携を解除」でトークンを削除。カレンダー上の予定は消さない

## 8. データ設計

テーブルは16個（パソコン・本番とも作成済み）。すべてのユーザーデータは `user_id` を持ち、**SQLは必ず `WHERE user_id = ログイン中のID` を付けて他人のデータに触れないようにする**。

| テーブル | 主な項目 | 用途 |
| --- | --- | --- |
| users | email, password_hash, name, role, status, last_login_at | 会員 |
| auth_tokens | user_id, selector, token_hash, expires_at, user_agent, last_used_at | 90日のログイン保持 |
| user_settings | company_view, schedule_view, task_reminders, event_reminders, timezone, install_done, install_dismissed | 表示形式の記憶、通知の初期値、アイコン化の案内 |
| companies | name, industry, stage, pref, url, site_url, mypage, memo | 企業（url＝採用ページ、site_url＝企業のHP。site_url は 2026-10-12 追加で、無ければアプリが自動で列を足す） |
| axes | name, weight, is_pref, sort | わたしの軸 |
| company_ratings | company_id, axis_id, score | 企業ごとの軸の評価 |
| events | company_id, type, title, event_date, event_time, place, online_url, items, auto_remind, google_event_id, google_etag | 予定（auto_remind = 0 でその予定の自動通知を外す） |
| reviews | company_id, event_id, review_date, feel, asked | ふりかえり |
| lessons | review_id, text | 次に活かしたいこと（課題） |
| lesson_evals | review_id, lesson_id, score(0〜3) | 課題の評価（メーターの計算） |
| tasks | company_id, title, due_date, auto_remind, done_at | タスク |
| reminders | target_type(task/event), target_id, remind_at, is_auto, sent_at | 通知の予定と送信済み |
| push_subscriptions | endpoint, p256dh, auth, user_agent | 端末ごとのプッシュ送信先 |
| notifications | kind, title, body, link, read_at | 通知ベル |
| access_daily | day, visitor_key, user_id, views | アクセス数（IPは保存しない） |
| calendar_accounts | provider, credentials(暗号化), calendar_id, sync_token, channel_id | Google連携 |

コード値

- 選考段階 `stage`：interest=気になる, entry=エントリー, es=書類選考, int1=一次面接, int2=二次面接, final=最終面接, offer=内定, out=見送り
- 予定の種類 `type`：briefing=説明会, es=ES締切, webtest=Webテスト, interview=面接, internship=インターン, other=その他
- 手応え `feel`：1=散々, 2=いまいち, 3=ふつう, 4=まずまず, 5=手応えあり
- 評価 `score`：0=できなかった(+0%), 1=少しできた(+15%), 2=だいたいできた(+30%), 3=できた(+50%)

## 9. セキュリティの決まりごと

- すべての出力は `h()`（htmlspecialchars）でエスケープ
- DBは PDO のプリペアドステートメントだけを使う
- POST・PUT・DELETE は CSRFトークンを確認
- ログインはセッションID再生成（`session_regenerate_id(true)`）。ログイン失敗が続いたら一時的に待たせる
- `config/config.php`（DBのパスワード）と `config/keys.php`（VAPID鍵、Googleの鍵、暗号化キー。`php bin/setup-keys.php` で作成）は共有・コミットしない
- オンラインURLは https:// のみ。マイページ欄にはパスワードを書かない注意書き
- 管理者でも会員の中身とパスワードは見られない。IPアドレスは保存しない
- 本番は `debug = false`、環境チェック画面は外から開けない

## 9-2. 実装のしくみ（2026-10-12 時点）

- 画面はすべて同じ HTML（`src/pages/app.php`）を返し、中身は `public/assets/app.js` がプロトタイプと同じ関数で描く。URL は History API で切り替える
- ログイン中は、保存のたびに API（`/api/...`、`src/api.php`）に送り、返ってきた最新のデータ一式で描き直す。デモ画面は `src/demo.php` のサンプル JSON を使い、画面の中だけで変更する（保存 API は 401）
- 通知・ふりかえりの声かけ・後片付けは `bin/cron-notify.php`（1分ごと）、Googleカレンダーの同期は `bin/cron-calendar.php`（5分ごと）
- 通知の「完了にする」ボタンは、署名つきトークンで `/api/push/done` を呼ぶ（Service Worker からなので CSRF の代わりに署名で確かめる）
- ログイン失敗はメールアドレスごとに数え、5回目から待ち時間を入れる（IPアドレスは使わない。記録は `storage/throttle`）

## 10. 実装の進め方
